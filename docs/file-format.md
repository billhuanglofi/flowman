# Flowman file format

Flowman keeps a single source of truth in YAML. Generated cURL and `.http` files are views, not inputs.

## Workspace layout

```text
flowman.yaml
envs/
  uat.yaml
  ppd.yaml
requests/
  payment/
    create.request.yaml
flows/
  payment/
    create-payment.flow.yaml
```

## `flowman.yaml`

The root file names the project, default environment, and the canonical file list.

```yaml
version: v1
name: flowman-example
default_env: uat
environments:
  - envs/uat.yaml
  - envs/ppd.yaml
requests:
  - requests/payment/create.request.yaml
flows:
  - flows/payment/create-payment.flow.yaml
```

## Environment files

Environment files hold base URLs, endpoint aliases, Oracle env var names, and trace defaults.

```yaml
version: v1
name: uat
base_url: https://uat.api.example.test
endpoints:
  - name: payments
    path: /payments
oracle:
  dsn_env: FLOWMAN_UAT_ORACLE_DSN
  user_env: FLOWMAN_UAT_ORACLE_USER
  password_env: FLOWMAN_UAT_ORACLE_PASSWORD
trace:
  transaction_id:
    header: X-Transaction-ID
    json_paths:
      - $.transaction_id
      - $.data.transactionId
    regex: 'transaction_id=([A-Za-z0-9_-]+)'
  poll_interval: 2s
  timeout: 30s
```

Rules:

- Store env var names, not secret values
- Keep base URLs and endpoint aliases environment specific
- Put shared transaction ID extraction defaults here when they apply to many requests

## Request files

Request files define HTTP input and optional request specific trace rules.

```yaml
version: v1
name: create payment
method: POST
endpoint: payments
path: /v1/payments
query:
  - name: dry_run
    value: "false"
headers:
  - name: Content-Type
    value: application/json
body:
  mode: json
  raw: |-
    {
      "amount": "12.34",
      "currency": "USD"
    }
trace:
  transaction_id:
    header: X-Transaction-ID
```

Supported request shape in stage 1:

- `method`
- `url`, or `endpoint` plus `path`
- `query`
- `headers`
- body `mode` of `raw`, `json`, or `form`
- per request trace config
- `import_warnings` for subset conversions

## Flow files

Flow files group one or more request steps.

```yaml
version: v1
name: create payment flow
description: Fixture flow for creating a payment and tracing its PROCESS_STATE journey.
steps:
  - name: create payment
    request: requests/payment/create.request.yaml
    trace: true
  - name: inspect process state
    request: requests/payment/create.request.yaml
```

Stage 1 uses flow files for grouping and step ordering inside Flowman. Exporters may warn when a downstream format cannot represent multi step sequencing losslessly.

## Generated artifacts

Generated cURL and `.http` outputs include a do not edit marker:

```text
Generated by Flowman. Do not edit; edit canonical YAML instead.
```

Rules:

- Generated files are deterministic
- Generated files should live under `.flowman/generated/` by default
- Generated files must not become the team source of truth
- Generated files should not contain raw secret values unless an explicit unsafe flag is used

## Secret redaction rules

Flowman treats these headers as sensitive by default:

- `Authorization`
- `Cookie`
- `Set-Cookie`
- `X-API-Key`
- `Proxy-Authorization`

Sensitive headers are stored as env references or redacted output values. Docs, evidence, logs, and generated files should never contain raw runtime values.
